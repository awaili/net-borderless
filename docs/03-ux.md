# 03 · 交互与界面设计

版本 v0.1（草案） · 2026-09-30 · 对应 PRD v0.1

---

## 1. 设计基调

**"仪表，而非开关。"**

Shadowrocket 的界面是一个巨大的设置面板。Aegis 的第一屏是**当前网络状态的仪表盘**——用户打开 App 的第一眼就能回答三个问题：

1. 现在通不通？
2. 流量走的哪条路？
3. 如果有问题，是什么问题？

复杂度分层原则：**一眼 → 一点 → 一折**。主页面一眼可读，细节最多点一次，原始日志/数据永远折叠在第三层。

## 2. 信息架构（5 Tab，移动端）

```
┌─ 状态 ─┬─ 连接 ─┬─ 规则 ─┬─ 节点 ─┬─ 我的 ─┐
```

| Tab | 一眼 | 一点 | 一折 |
|---|---|---|---|
| **状态** | 代理开关、当前节点、实时速率、今日流量、连通性色点 | 策略组快捷切换、一键诊断按钮 | 最近诊断报告 |
| **连接** | 实时连接表（域名 → 节点 → 速率） | 单连接详情：完整五元组、命中规则链、RTT 曲线 | 连接日志导出 |
| **规则** | 规则分组列表 + 命中数排序 | 单条规则编辑、建议卡片 | 规则集版本历史/diff |
| **节点** | 策略组卡片（当前选中、组健康色点） | 组内节点列表（延迟曲线、失败率、摘除状态） | 探活历史、手动强制摘除 |
| **我的** | Profile 列表 | 订阅管理、设置、流量图表 | 配置源码视图（YAML + diff） |

桌面端：状态与连接合并为常驻小面板（托盘展开）；规则/节点/配置为完整窗口。

## 3. 关键流程

### 3.1 首次配置向导（目标：90 秒可用）

```
导入方式三选一：
  ① 粘贴订阅链接（最常见）
  ② 扫二维码
  ③ 导入 sing-box / Clash / Shadowrocket 备份文件
     ↓
订阅解析 → 节点探活（进度环，"已测 12/34 个节点"）
     ↓
推荐策略组：根据测速结果自动建议（"大部分节点可解锁流媒体，已为你创建媒体组"）
     ↓
规则模板选择：推荐规则集（签名版）+ 可选自定义
     ↓
自动执行首次一键诊断 → 展示"一切正常 ✓"或逐项解释问题
```

向导结束态必须是**已验证的可用状态**，而不是"配置好了你自己试试"。

### 3.2 一键诊断（差异化入口）

- 入口：状态页最醒目的非开关按钮；节点故障自动切换时也会生成诊断报告并推送。
- 执行：8 项 checklist（PRD F6）逐项跑，每项有独立进度与结果色。
- 输出：**一句话结论 + 建议动作按钮**。例：

  > ❌ Netflix 无法观看
  > 节点 Tokyo-01 不支持 Netflix 解锁（检测返回地区：JP，账号区不匹配）。
  > [ 切换到组内已验证可解锁的节点 Osaka-02 ]

  按钮直接执行修复动作，不引导用户去设置里找。

### 3.3 规则建议卡片（学习式分流，PRD F3）

- 规则页顶部卡片流（最多同时 3 张，超出进"建议中心"）：

  > ⚠️ openai.com 过去 7 天走直连失败 42 次（成功率 31%）
  > [ 添加规则走 PROXY 组 ] [ 忽略 ] [ 永不再提醒 ]

- 卡片只在"证据充分"时出现（≥ 20 次样本），避免打扰；采纳后写入用户规则层（优先级最高、可一键撤销）。

### 3.4 节点故障自动切换（无感原则）

- 自动切换发生 → 状态页色点短暂变化 + 通知中心轻通知（可关）。
- 用户手动选中的节点故障 → 不自动改用户选择，改为提示卡片（"你选择的 Tokyo-01 已不可用，已临时回落到 Osaka-02，[确认切换] [保持尝试]"）。**原则：自动化不覆盖人的显式意志。**

## 4. 状态页设计（示意）

```
┌───────────────────────────────┐
│  AEGIS          [ ⏻ 开启中 ]   │
│                               │
│   ● 网络健康 96 分              │
│   当前节点: Osaka-02 · 38ms    │
│   ▲ 上传 1.2 MB/s              │
│   ▼ 下载 8.7 MB/s   今日 2.1GB │
│                               │
│   [策略组: 自动选择 ▾]           │
│   [ 🔍 一键诊断 ]               │
│                               │
│   ⚠ 1 条规则建议 (openai.com)   │
└───────────────────────────────┘
```

健康分（0~100）综合：探活成功率、延迟 EWMA、近期诊断结果。分值可点开看构成——**可解释性贯彻到 UI**。

## 5. 平台差异

| | iOS | macOS/Windows |
|---|---|---|
| 状态 | 仪表盘 + 快捷切换 | 菜单栏/托盘速览，展开面板 |
| 连接 | 最多展示 500 条 + 搜索 | 全量 1 万条 + 过滤器 + 流式 |
| 规则 | 浏览 + 建议卡片 | 完整编辑器 + Git 同步 + diff |
| 诊断 | 全量 | 全量 + 定时自动体检（可配） |
| 配置 | Profile 切换 | 源码编辑、热重载、格式校验 |

## 6. 文案与语气规范

- 诊断结论**先说人话再说数据**："节点不通" 而非 "TCP handshake timeout"。
- 永不出现"未知错误"；无法解释时如实说"未能定位原因"并给出上报（可选、脱敏）入口。
- 所有自动行为的通知都带撤销入口。
