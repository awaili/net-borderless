# 01 · 产品需求文档（PRD）

版本 v0.1（草案） · 2026-09-30 · 工作代号 **Aegis（神盾）**

---

## 1. 一句话定位

**跨平台、可观测、自适应的开源代理系统**："它不只是一个开关，而是能告诉你发生了什么、并自己修好的网络系统。"

## 2. 问题定义

以 Shadowrocket 为代表的现有产品存在四个**结构性缺口**，这正是本产品的机会：

| # | 缺口 | 现状 | 用户痛感 |
|---|---|---|---|
| 1 | 规则是静态的 | 用户手工维护分流规则 | "为什么这个 App 不通？"没人能回答 |
| 2 | 运行是黑盒 | 无连接面板、无诊断 | 出问题只能换节点碰运气 |
| 3 | 单平台闭源 | 能力锁在 iOS 里 | 桌面/移动体验割裂，无法审计 |
| 4 | 配置是"文件"不是"代码" | 无版本、无签名、无同步 | 订阅被篡改无从感知，多设备靠手动复制 |

## 3. 目标用户（Persona）

| | 画像 | 核心诉求 | 主要使用场景 |
|---|---|---|---|
| **U1** 机场重度用户 | iOS 主力，订阅 2~5 个机场，不懂技术细节 | "开着就别让我管" | 手机全局代理看流媒体 |
| **U2** 自建 VPS 的工程师 | 桌面 + 移动双端，有 1~3 台自管服务器 | 可控、可排障、配置可版本化 | 工作 + 开发调试 |
| **U3** 家庭管理员 | 给父母/伴侣配好设备的中间人 | 配一次就别再找我 | 家人设备远程维护 |
| 反目标用户 | 需要集中管控的企业 IT | 明确 **v1 不做**（无设备管理、无策略下发） | — |

**设计权重**：U2 > U1 > U3。U2 是早期种子与口碑来源；U3 是 2.0（Mesh 阶段）的扩张方向。

## 4. 产品原则

1. **数据不出本地**：连接统计、学习式建议、诊断全部本地计算；遥测默认关闭且 opt-in，上报内容 schema 公开。
2. **默认安全**：Kill switch 默认开启；核心崩溃或节点全断时流量 DROP 而非直连。
3. **诊断是一等公民**：任何转发决策可追溯（规则命中记录）；任何故障可解释（诊断输出人话结论）。
4. **开源核心，可复现构建**：核心引擎与规则集格式开源；UI 可开源可商业。
5. **兼容生态**：支持导入 sing-box / Clash 配置与现有订阅链接，迁移成本为零。

| 产品 | 平台 | 价格 | 可观测性 | 自适应 | 开源 | 关键弱点 |
|---|---|---|---|---|---|---|

**差异化楔子（wedge）**：自适应选路 + 内置诊断 + 全平台一致体验 + 开源核心。竞品在单点上各有覆盖，没有一家把四件事同时做对。

## 6. 功能规格

优先级定义：P0 = 1.0 必须；P1 = 1.0~1.x 差异化核心；P2 = 2.0 方向。

### F1 协议栈

| 优先级 | 出站协议 | 说明 |
|---|---|---|
| P0 | Shadowsocks-2022 | 抗重放/主动探测；兼容 ss:// 订阅导入 |
| P0 | Trojan | 生态存量最大 |
| P0 | VLESS + REALITY | 抗探测天花板，无需域名证书 |
| P0 | HTTP / SOCKS5 | 基础出站与级联 |
| P0 | WireGuard | 自建用户刚需，也是 Mesh 的地基 |
| P1 | Hysteria2 / TUIC v5 | QUIC 系，弱网吞吐显著优势 |
| P1 | SSH | 工程师小众刚需，成本低 |
| P2 | 链式代理（多跳） | 入口 → 中继 → 出口，节点互访场景 |

**验收标准**：每个 P0/P1 协议与 sing-box 官方实现做互通测试（双向：我们连它的服务端 / 它的客户端连我们的服务端），进 CI。

### F2 规则引擎

- **匹配器**：DOMAIN / DOMAIN-SUFFIX / DOMAIN-KEYWORD / DOMAIN-REGEX / IP-CIDR / GEOIP / PORT / PROTOCOL（嗅探结果：http/tls/quic/dtls，含 SNI）/ PROCESS（仅桌面）。
- **逻辑表达式**（现有产品普遍不支持嵌套逻辑）：
  ```
  AND((DOMAIN-SUFFIX,netflix.com), NOT(IP-CIDR,10.0.0.0/8)) -> PROXY_MEDIA
  ```
- **RULE-SET**：远程规则集，支持签名 + 版本号 + 增量更新 + 本地缓存；格式兼容 sing-box rule-set，另有带签名自有格式。
- **命中记录**：每条规则带命中计数，UI 可排序（喂给 F3 的学习建议）。
- **兜底**：未匹配流量显式声明 MATCH 策略；不写则默认 REJECT 并在诊断中提示。

**验收标准**：10 万条规则集编译后单次匹配 p99 < 50µs；匹配器 fuzz 测试通过；规则集热更新不中断连接。

### F3 策略组与自适应（核心差异化）

策略组类型：

| 类型 | 级别 | 说明 |
|---|---|---|
| select | P0 | 手动选择 |
| url-test | P0 | 定时探活，EWMA 延迟 + 容忍度（tolerance）内不抖动 |
| fallback | P0 | 主备优先级切换 |
| load-balance | P1 | round-robin / least-latency |
| **smart** | P1 | 综合延迟 EWMA × 失败率 × 突发流量惩罚自动选路，用户不感知 |

**探活机制**：TCP 握手 RTT + HTTP 首字节延迟双探针；连续 N 次失败自动摘除，恢复探活通过后回融（避免雪崩震荡）。

**学习式分流建议**（本地）：
- 触发条件示例：某域名连续 7 天命中 DIRECT 但失败率 > 30%；或某域名频繁命中 REJECT 被客户端重试。
- 呈现：规则页"建议卡片"——"过去 7 天 openai.com 走直连失败 42 次，建议加入 PROXY 组？［采纳 / 忽略 / 永不再提］"。
- 约束：**只建议、不自动改规则**；统计数据仅存本地 SQLite，90 天滚动。

**验收标准**：单节点故障 → 组内自动切换 < 30 秒且用户无感；摘除/回融行为有可复现的故障注入测试。

### F4 DNS

- 上游：DoH / DoT / DoQ（P1），bootstrap IP 可配置。
- **Split DNS**：DNS 策略与规则引擎联动（域名命中 PROXY 规则 → 该域解析走代理通道）。
- Fake-IP 模式（P1）：消除 TUN 下 DNS 先行泄露。
- **防泄露**：所有 DNS 出站必须走显式声明的通道；未配置时拒绝解析并产生诊断警告，绝不静默回退系统 DNS。

**验收标准**：dnsleaktest.com 双端全零泄露；开启代理后系统 DNS 请求抓包为零。

### F5 可观测性

- **连接面板**：实时连接表（进程/来源 → 域名/SNI → 命中规则 → 策略组/节点 → RTT → 当前速率 → 累计字节），WS 推送。
- **流量统计**：按域名 / 节点 / 规则三维聚合，日/周图表，保留 90 天。
- **节点健康**：每个节点延迟历史曲线、失败率、近期摘除记录。

**验收标准**：1 万并发连接下 UI 刷新延迟 < 500ms；连接表常驻内存 < 8MB。

### F6 诊断（核心差异化）

**一键诊断**，按链路顺序执行并输出人话结论：

1. 引擎自检（核心版本、配置加载、规则数）
2. DNS 解析验证（上游可达性、污染检测）
3. 规则命中解释（"该域名命中第 37 条规则 → 走了 MyProxy 组的节点 A"）
4. 节点探测（当前链路握手 RTT / TLS / 首字节）
5. 目标连通（对疑难域名做全链路追踪：DNS → 规则 → 节点 → 目标，逐步截图式呈现）
6. 泄露检测：DNS 泄露 / IPv6 泄露 / WebRTC 泄露（浏览器场景给出指引）
7. 流媒体解锁检测（P1）：Netflix / Disney+ / ChatGPT / YouTube Premium 分区结果
8. 长期健康分：综合 7 天数据给连接质量评分与建议

输出为**结构化报告**：结论一句话（"Netflix 不通是因为节点 A 不支持解锁，建议切换到组内节点 B"）+ 详细数据折叠展示 + 一键执行建议动作。

**验收标准**：建立故障注入用例库（节点挂 / DNS 污染 / 规则写错 / ISP 封锁端口），诊断结论正确率 > 90%。

### F7 配置、订阅与同步

- **配置即代码**：声明式 YAML；多 Profile 管理，秒级切换；变更带 diff 视图。
- **生态兼容（P1）**：导入 sing-box JSON / Clash YAML，导入为只读副本并映射到自有 schema。
- **订阅**：URL 订阅（base64 / ss:// / trojan:// / vless:// 等标准 URI）P0；**签名订阅清单**（内容哈希 + 版本 + 签名，防篡改）P1。
- **同步**：Git 仓库同步（P1，桌面端优先）；端到端加密云同步（P2，Pro 功能）。

### F8 个人 Mesh（P2，2.0 方向）

- 一键把 1~N 台 VPS / 家庭设备组成 WireGuard mesh。
- 家庭成员共享出口：每成员独立带宽上限与可选审计策略（家长场景）。
- 目标：把"个人翻墙"从"买机场"升级为"自建共享"，Shadowrocket 完全没有涉足的方向。

### F9 安全与隐私

- Kill switch（P0，默认开）：见原则 2；实现层面默认路由指向 TUN + 平台包过滤兜底。
- 凭据（订阅 URL、节点密钥）仅存 OS Keychain / Credential Manager；配置库 AES 加密。
- iOS / Android 应用锁（生物识别，P1）。
- 遥测默认关闭；opt-in 后仅上报匿名功能使用计数，schema 公开可审计。

## 7. 非功能需求

| 指标 | 目标 | 原因 |
|---|---|---|
| iOS NE 常驻内存 | < 40MB（上限 50MB） | 超限被系统杀，是 iOS 代理工具头号稳定性杀手 |
| iOS 开启代理到可用 | < 2s | Shadowrocket 同水位 |
| 桌面端空闲 CPU | < 1% 单核 | 常驻不讨嫌 |
| 桌面端吞吐 | 单核 ≥ 1Gbps（TCP 转发） | Wire 加密有硬件加速时不成为瓶颈 |
| 电池 | 连续使用 1h 额外耗电 < 5% | 移动端口碑 |
| 测试覆盖率 | 核心引擎 ≥ 80%，协议互通测试 100% 协议覆盖 | 开源信任基础 |
| 数据驻留 | 全部本地 | 见原则 1 |

## 8. 数据模型（概要）

核心实体：`Profile`（配置）、`Subscription`（订阅，含签名）、`Node`、`PolicyGroup`、`Rule / RuleSet`、`Connection`（实时）、`TrafficStat`（聚合）、`DiagReport`、`Suggestion`（学习建议）。详见架构文档 §6。

## 9. 发行与商业模式

- **开源策略**：核心引擎 GPL-3.0（防闭源分叉），规则集格式与诊断 SDK 宽松许可（MIT）；桌面端 GUI 开源；iOS/Android 端闭源收费（核心仍开源可复现）。
- **定价**（对齐并略高于 Shadowrocket，远低于 Surge）：
  - 桌面端：免费开源（获客与口碑入口）。
  - iOS：买断 $4.99（含全部功能）。
  - **Pro 订阅 $1.99/月 或 $14.99/年**：端到端云同步、诊断历史云端留存、Mesh 超过 3 名成员、规则建议高级模型更新。**原则：联网功能才收费，单机功能永不付费墙。**
- **发行渠道**：iOS 全球 App Store（**不含中国大陆区**）+ TestFlight 公测；macOS Developer ID 签名直分发；Windows 自签名 + Scoop/Winget；Android GitHub Releases / Play（视审核）。
- **法律姿态**：工具中立、不内置任何服务端资源、不在中国区发行；App Store VPN 类目按 5.4 条款准备完整材料（隐私政策、日志政策）。

## 10. 成功指标

- **北极星：MTTR（从网络异常发生到恢复正常的时长）**——Shadowrocket 的典型 MTTR 是"用户换节点碰运气直到成功"，不可测量；我们把诊断建议采纳率与自动切换耗时纳入同一口径。
- 支撑指标：
  - 自动切换中位耗时 < 30s（F3）
  - 诊断建议采纳率 > 40%
  - "零维护天数"：用户开启后连续无手动干预的天数（周活跃分布）
  - 桌面开源版 → iOS 付费转化率（口碑验证）

## 11. 明确不做（v1）

- ❌ 企业集中管控 / MDM
- ❌ 任何形式的机场分发、返利、分成
- ❌ 广告与第三方 SDK
- ❌ 中国大陆区发行
- ❌ 永久免费承诺之外的付费墙单机功能
